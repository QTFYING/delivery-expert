## 端点总览

| #   | Method | Path                          | 说明                          |
| --- | ------ | ----------------------------- | ----------------------------- |
| 1   | GET    | `/pay/:token`                 | 获取订单公开详情              |
| 2   | POST   | `/pay/:token/initiate`        | 发起在线支付（跳转收银台）    |
| 3   | POST   | `/pay/:token/offline-payment` | 线下备注登记（现金/其他方式） |
| 4   | GET    | `/pay/:token/status`          | 查询订单当前 H5 收款状态      |

共计 **4** 个端点。

> 说明：`orders.qrCodeToken` 的业务语义等同 `h5EntryToken`。它是订单级公开路由标识，用于将送货单二维码路由到对应订单 H5 页面，不承载收货人身份鉴权，也不是支付单标识。本文中的 `token` 均指该 H5 入口令牌。

## 1. 获取订单公开详情

- **GET** `/pay/:token`
- **描述**：根据订单公开入口令牌获取 H5 页面所需的完整订单信息，包括商户、客户、商品明细、当前收款状态等
- **是否鉴权**：否（公开页面路由）

**契约类型：** 响应：`PaymentOrderDetailResponse`

### 路径参数

| 参数  | 类型   | 说明                                                                                   |
| ----- | ------ | -------------------------------------------------------------------------------------- |
| token | string | URL 中的 H5 入口令牌，业务语义记作 `h5EntryToken`，当前实际字段为 `orders.qrCodeToken` |

**补充说明：**

- `summary` 由服务端基于 `items` 聚合生成，不依赖订单头保留 `skuName / lineAmount`
- H5 入口令牌仅承担公开路由职责，不承载订单自定义字段值、支付状态或支付金额
- `offlinePayment` 为空表示当前订单没有待展示的线下登记信息
- `paymentAction` 表示当前订单允许的在线支付动作，只表达服务端裁决后的业务能力，不表达按钮文案或页面布局
- `paymentAction.canInitiate` 必须同时满足订单本身可支付、订单未超过租户当前 `qrCodeExpiry` 支付有效期、所属租户已设置 `activePaymentChannel`，且当前生效渠道对应配置状态为 `available`
- 当订单超过租户当前 `qrCodeExpiry` 支付有效期，且订单尚未进入 `paid` 或 `pending_verification` 时，本接口仍返回 `200`，但会将 `status` 强制投影为 `expired`，`statusMessage` 返回统一超期提示，`paymentAction.canInitiate=false` 且 `paymentAction.canResume=false`
- 订单一旦进入 `paid` 或 `pending_verification`，支付有效期只阻断新的支付动作，不回滚既有终态

### 错误场景

| code  | 场景                       |
| ----- | -------------------------- |
| 1002  | 二维码路由已过期           |
| 40401 | 路由无效，对应的订单不存在 |

## 2. 发起在线支付

- **POST** `/pay/:token/initiate`
- **描述**：请求后端发起在线支付。后端会按租户当前生效支付渠道选择对应网关并返回收银台跳转链接；若当前存在未过期的 `paying` 在线支付尝试，则恢复同一笔收银台地址，不创建并发支付单。
- **是否鉴权**：否

**契约类型：** 请求：无 Body；响应：`InitiatePaymentResponse`

### 路径参数

| 参数  | 类型   | 说明                                                                                   |
| ----- | ------ | -------------------------------------------------------------------------------------- |
| token | string | URL 中的 H5 入口令牌，业务语义记作 `h5EntryToken`，当前实际字段为 `orders.qrCodeToken` |

**补充说明：**

- 本接口不接收金额参数，实际支付金额由服务端订单状态算定
- `cashierUrl` 为一次性支付跳转地址，不是订单静态字段
- `payableAmount` 为服务端按当前订单状态核算出的本次定额支付金额，前端不能修改

### 错误场景

| code  | 场景                                     |
| ----- | ---------------------------------------- |
| 1001  | 订单已支付完毕（`paid`），不允许重复发起 |
| 1003  | 支付状态已变化，无法恢复或新建支付尝试   |
| 1004  | 当前租户支付渠道不可用                   |
| 1005  | 订单已超过租户支付有效期                 |
| 40401 | 订单路由不存在                           |
| 50001 | 支付网关统一下单调度失败                 |

### 业务规则

- 仅状态为 `unpaid` 与“上一轮支付尝试已失效且订单仍可支付”的 `expired` 订单可以由本路由创建新的在线支付尝试。
- 当最新在线支付尝试仍为未过期 `paying` 且存在可恢复的收银台地址时，本路由直接返回该支付尝试的 `cashierUrl`，不创建新的 `payment_orders` 记录。
- 当状态为 `expired` 时，可能表示上一轮支付尝试已失效，也可能表示订单已超过租户支付有效期；是否允许重新支付必须以 `paymentAction.canInitiate` 与本接口返回结果为准
- 若订单已超过租户当前 `qrCodeExpiry` 支付有效期，本路由直接返回 `1005`，不恢复旧收银台，也不创建新的 `payment_orders` 记录
- 若订单所属租户不存在 `activePaymentChannel`，或当前生效渠道对应的配置状态不是 `available`，本路由直接返回业务错误，不进入网关建单；前端按返回的错误状态展示不可支付提示。
- 成功下发收银台 URL 的同时，后端将订单状态迁移为 `paying`。
- 在线支付成功回调只有在该支付尝试仍处于 `paying`，且金额仍与订单当前待支付金额一致时才会入账；已失效或金额已过时的旧支付尝试回调将被忽略。
- `cashierUrl` 不是订单固定字段；只有用户点击支付后，后端向支付渠道发起预下单时才会动态返回。
- H5 前端获取到 `cashierUrl` 后直接跳转，在用户完成支付关掉页面后，利用 `/pay/:token/status` 的轮询检查最终核实。

## 3. 线下支付登记

- **POST** `/pay/:token/offline-payment`
- **描述**：登记线下支付备注（现金支付或其他方式已支付），不走支付网关，不由 H5 直接确认入账
- **是否鉴权**：否

**契约类型：** 请求：`SubmitOfflinePaymentRequest`；响应：`SubmitOfflinePaymentResponse`

### 路径参数

| 参数  | 类型   | 说明                                                                                   |
| ----- | ------ | -------------------------------------------------------------------------------------- |
| token | string | URL 中的 H5 入口令牌，业务语义记作 `h5EntryToken`，当前实际字段为 `orders.qrCodeToken` |

**补充说明：**

- `paymentMethod=cash` 或 `paymentMethod=other_paid` 时必须填写 `remark`
- 返回值中的 `status` 为 H5 页面下一步应展示的收款状态

### 错误场景

| code  | 场景                              |
| ----- | --------------------------------- |
| 40001 | paymentMethod 不是合法值          |
| 40002 | 现金支付时 remark 为空            |
| 1005  | 订单已超过租户支付有效期          |
| 40401 | 订单不存在                        |
| 40402 | 订单状态不是 `unpaid`，不允许操作 |

### 业务规则

| 支付方式     | 状态流转                          | 说明                           |
| ------------ | --------------------------------- | ------------------------------ |
| `cash`       | unpaid → **pending_verification** | 提交备注后等待 Tenant 财务核销 |
| `other_paid` | unpaid → **pending_verification** | 提交备注后等待 Tenant 财务确认 |

- 两种线下方式都必须填写 remark（备注），不可为空
- H5 端 `other_paid` 只作为备注登记能力，不直接把订单标记为已支付
- 若订单已超过租户当前 `qrCodeExpiry` 支付有效期，本路由直接返回 `1005`，不创建线下登记支付单
- 提交成功后，响应中返回更新后的订单状态和 offlinePayment 信息

## 4. 查询订单当前 H5 收款状态

- **GET** `/pay/:token/status`
- **描述**：根据 H5 入口令牌查询当前订单在 H5 页面应展示的收款状态。该接口主要用于在线支付发起后轮询网关异步回调结果；`token` 仅用于定位订单公开页面，不代表某一次支付尝试，也不是支付单令牌。
- **是否鉴权**：否

**契约类型：** 响应：`PaymentStatusResponse`

### 路径参数

| 参数  | 类型   | 说明                                                                                                                                    |
| ----- | ------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| token | string | URL 中的 H5 入口令牌，业务语义记作 `h5EntryToken`，当前实际字段为 `orders.qrCodeToken`；用于定位订单，不用于定位某一条 `payment_orders` |

**补充说明：**

- `status` 为 H5 当前应展示的订单收款状态，不是某一条支付单状态的直传
- `paidAmount`、`paidAt` 在支付完成后返回
- `selectedPaymentMethod` 用于页面恢复当前支付方式展示
- `paymentAction` 表示当前允许的在线支付动作；前端是否展示“继续支付”或“重新支付”应以该字段为依据
- 当订单超过租户当前 `qrCodeExpiry` 支付有效期，且订单尚未进入 `paid` 或 `pending_verification` 时，本接口会将 `status` 投影为 `expired`，并通过 `statusMessage` 返回统一超期提示

### 语义边界

- `/pay/:token/status` 不是“按支付单 token 查询某一次支付尝试状态”的接口；当前路径中的 `token` 与 `/pay/:token`、`/pay/:token/initiate` 使用同一个 H5 入口令牌。
- 返回的 `status` 是订单当前在 H5 页面应展示的收款状态，不是 `payment_orders.status` 的无条件直传。
- 在线支付可因超时或失败产生多轮支付尝试；本接口始终面向订单当前状态，后端可结合订单状态、订单已收金额与最新支付单状态进行判定。
- `paymentAction.canResume=true` 表示当前未过期在线支付尝试允许继续跳转原收银台；`paymentAction.canInitiate=true` 表示允许重新发起在线支付。
- `paymentAction.canInitiate` 还必须结合订单支付有效期、租户 `activePaymentChannel` 与当前生效渠道配置状态共同判断；超出支付有效期、未设置生效渠道、未配置、待校验、停用或无效时都应为 `false`
- `paymentAction.expiresAt` 是后端创建收银台时传给支付网关的有效截止时间，不是支付网关查询后的实时剩余时间。
- `expired` 可能来自上一笔在线支付尝试超时，也可能来自订单超过租户支付有效期；是否允许重新发起支付必须以 `paymentAction.canInitiate` 为准。
- 当 `statusMessage` 返回“订单已超过商户设置的支付有效期（XX天），请联系商户处理”时，前端应视为强终态展示，不再展示可提交的在线支付或线下登记入口
- 已进入 `paid` 或 `pending_verification` 的订单不会因为超过支付有效期而被本接口回写为 `expired`
- 本接口必须返回新鲜状态，不允许浏览器或反向代理缓存。

### 缓存控制

`GET /pay/:token/status` 必须返回：

```http
Cache-Control: no-store
Pragma: no-cache
Expires: 0
```

### 前端轮询策略

```
前 30 秒：每 2 秒查询一次 /status
30 秒至 2 分钟：每 5 秒查询一次 /status
超过 2 分钟：停止自动轮询，提示用户手动刷新
页面重新可见时：主动刷新一次 /status
终止条件：status 变为 paid、pending_verification、expired，或 paymentAction.canResume=false 且 canInitiate=true
```

## 类型定义汇总

### PaymentOrderStatus（H5 订单收款状态）

统一使用共享闭集 `PaymentOrderStatus`。业务含义如下：

| 状态                   | 中文   | 说明                                             | H5 页面展示                |
| ---------------------- | ------ | ------------------------------------------------ | -------------------------- |
| `unpaid`               | 待支付 | 初始状态，等待用户去支付                         | 蓝色面板，"去支付"按钮可点 |
| `paying`               | 支付中 | 已通过 `/initiate` 发起跳转，等待网关异步回调    | 黄色面板，展示"支付确认中" |
| `pending_verification` | 待核销 | 线下现金支付已登记，等待 Tenant 财务核销         | 橙色面板，"订单待核销"     |
| `paid`                 | 已完成 | 支付成功或已通过其他方式确认全款                 | 绿色面板，"订单已完成"     |
| `expired`              | 已过期 | 上一轮在线支付尝试失效，或订单超过商户支付有效期 | 灰色面板，无法进行交互动作 |

> 补充说明：`expired` 不等于一定允许重新支付。若只是上一轮在线支付尝试失效，且订单仍在租户支付有效期内，则允许再次调用 `POST /pay/:token/initiate`；若 `expired` 来自订单超过商户支付有效期，则 `paymentAction.canInitiate=false`，`POST /pay/:token/initiate` 与 `POST /pay/:token/offline-payment` 都会返回 `1005`。

## 跨项目关联

### 与 Tenant 端的关联

| H5 操作                                           | 关联的 Tenant 端操作                                                          |
| ------------------------------------------------- | ----------------------------------------------------------------------------- |
| 线下支付（现金）→ 状态变为 `pending_verification` | Tenant 财务调用 `POST /orders/{id}/cash-verifications` 核销 → 状态变为 `paid` |
| 在线支付成功 → 状态变为 `paid`                    | Tenant 收款流水 `GET /payments` 中新增一条记录                                |
| 订单详情展示商品明细                              | Tenant 端创建订单时录入的 order_items                                         |

### 与 Admin 端的关联

| H5 操作  | 关联的 Admin 端数据                              |
| -------- | ------------------------------------------------ |
| 支付成功 | Admin `GET /payments` 跨租户收款流水中可见       |
| 支付成功 | Admin `GET /reconciliation/daily` 对账明细中计入 |
