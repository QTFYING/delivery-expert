# H5 客户订单详情与支付端

> 本文档只补充 H5 支付页无法从 Swagger 与共享 `contracts` 直接推导的业务语义
> 请求/响应结构、错误码、字段可选性与示例以 Swagger 和 `packages/types` 为准

## 一、H5 入口令牌

`orders.qrCodeToken` 的业务语义等同 `h5EntryToken`，只用于打开 `/pay/:token` 对应订单公开页面。

该 `token` 不是用户身份凭证，不是支付单标识，也不是网关内部单号。H5 支付状态轮询仍使用同一个入口令牌。

## 二、接口

### 2.1 获取订单公开详情

- **GET** `/pay/:token`

**补充说明：**

- `paymentAction` 与 `offlinePaymentAction` 是服务端裁决后的动作能力，不表达按钮文案或页面布局
- 订单支付有效期按北京时间下单日期自然日计算；例如 2026-05-01 13:23 下单且有效期 30 天，最后可支付日为北京时间 2026-05-30
- 订单超过租户当前支付有效期且尚未进入 `paid / pending_verification` 时，H5 展示状态投影为 `expired`
- 已进入 `paid / pending_verification` 的订单不会因为超过支付有效期而回滚为 `expired`

### 2.2 发起在线支付

- **POST** `/pay/:token/initiate`

**业务规则：**

- H5 不提交支付金额，实际应付金额由服务端按订单当前待支付金额计算
- 存在未过期 `paying` 在线支付尝试时，服务端恢复同一笔收银台地址，不创建并发支付单
- 超过租户支付有效期、租户不可收款或当前生效渠道不可用时，不恢复旧收银台，也不创建新的支付单
- 在线支付成功回调只有在支付单仍处于 `paying` 且金额仍匹配订单当前待支付金额时才允许入账

### 2.3 线下支付登记

- **POST** `/pay/:token/offline-payment`

**业务规则：**

- H5 线下登记只产生待确认事实，不直接把订单标记为已支付
- `cash` 与 `other_paid` 都进入 `pending_verification`，必须由 Tenant 财务确认后才入账
- 超过租户支付有效期或租户不可收款时，不创建线下登记支付单

### 2.4 查询订单当前 H5 支付状态

- **GET** `/pay/:token/status`

**补充说明：**

- 返回的是订单在 H5 页面应展示的聚合支付状态，不是 `payment_orders.status` 的无条件直传
- `expired` 可能来自上一轮在线支付尝试超时，也可能来自订单超过租户支付有效期；是否能重新发起支付以 `paymentAction.canInitiate` 为准
- 本接口用于支付后轮询，必须读取新鲜状态，不应被浏览器或反向代理缓存

## 三、支付状态边界

- 在线支付：H5 跳转收银台并轮询状态；网关回调、入账与订单状态推进由后端完成
- 线下登记：H5 只提交备注；Tenant 财务确认后才生成收款事实
- `cashierUrl` 是一次性动态收银台地址，不应缓存为订单长期入口
- `payableAmount` 是服务端计算结果，前端不得自行改价
