# 收单吧 SaaS 平台 — API 架构总览

> 本文档面向前端团队，说明 Admin / Tenant / H5 三端 API 的业务边界、全局约定和跨端协作关系。
> 闭集枚举事实源统一维护在 `packages/types/src/enums`。

---

## 一、业务全景

```
┌─────────────────────────────────────────────────────────────────┐
```

### 核心业务链路

```
平台开通租户 → 租户入驻配置 → 录入/导入订单 → 生成收款码 → 客户扫码付款
     │              │              │              │              │
   Admin          Tenant         Tenant         Tenant          H5
     │              │              │              │              │
     ▼              ▼              ▼              ▼              ▼
  审核资质      配置团队角色    管理订单生命周期   打印发货      支付→核销→对账
```

## 二、全局统一约定

### 2.1 Base URL

```text
https://api.platform.com/api/v1
```

### 2.2 访问方式

| 接口类型                   | 访问方式                                                |
| -------------------------- | ------------------------------------------------------- |
| 后台接口（Admin / Tenant） | `Authorization: Bearer <access_token>`（JWT）           |
| C端收款页接口              | 无 JWT，通过 URL 中的 H5 入口令牌路由到对应订单 H5 页面 |
| Lakala Webhook 回调        | 无 JWT，后端校验拉卡拉签名                              |

### 2.3 统一响应格式

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

### 2.4 分页约定（Query 参数）

| 参数       | 类型     | 默认值 | 说明               |
| ---------- | -------- | ------ | ------------------ |
| `page`     | `number` | `1`    | 页码，从 1 开始    |
| `pageSize` | `number` | `20`   | 每页条数，最大 100 |

### 2.5 业务错误码表

| code   | 含义                     |
| ------ | ------------------------ |
| `0`    | 成功                     |
| `1001` | 订单已支付，禁止重复操作 |
| `1002` | 二维码已过期             |
| `1003` | 支付中，禁止并发发起     |
| `1004` | 当前租户支付渠道不可用   |
| `4001` | 未登录或 Token 已失效    |
| `4003` | 无权限访问该资源         |
| `4004` | 资源不存在               |

### 2.6 时区约定

所有时间均以 **ISO 8601 UTC 格式** 传输（含 `Z` 后缀），前端展示统一转换为当地时区。

### 2.7 前端共享契约落点

- 枚举事实源统一维护在 `packages/types/src/enums/`
- 请求、响应和资源结构统一维护在 `packages/types/src/contracts/`
- 通用分页与响应包装等共享结构统一维护在 `packages/types/src/common/`
- Swagger / OpenAPI 负责传输结构、可选项、`nullable` 与示例展示

## 三、三端 API 关联矩阵

三个前端共享同一个后端，很多**资源是同一张表**，只是**视角和权限不同**：

| 后端资源      | Admin 视角                                          | Tenant 视角                                           | H5 视角                                      |
| ------------- | --------------------------------------------------- | ----------------------------------------------------- | -------------------------------------------- |
| **Auth**      | 平台账号登录 + 会话刷新 + 当前用户信息              | 租户账号登录 + 会话刷新 + 当前用户信息                | 无需登录（通过 H5 入口令牌打开订单 H5 页面） |
| **Tenant**    | CRUD + 审核 + 冻结 + 续费（全量）                   | 提交资质材料 + 查询资质状态 + 支付渠道配置            | —                                            |
| **User**      | 跨租户管理所有用户                                  | 仅管理本租户下用户                                    | —                                            |
| **Order**     | 跨租户查看/审计所有订单，不承担导入、打印和催款动作 | 本租户订单 CRUD + 订单批量导入 + 打印 + 账期管理      | 单个订单只读                                 |
| **Payment**   | 跨租户收款流水汇总 + 支付渠道配置兜底               | 本租户收款 + 现金核销 + 财务对账 + 支付渠道配置       | 发起支付（受当前生效支付渠道约束）           |
| **Analytics** | 平台级聚合指标                                      | 本租户经营数据                                        | —                                            |
| **Billing**   | 套餐 / 合同 / 发票管理（运营）                      | 无独立计费操作入口                                    | —                                            |
| **Security**  | 角色模板 + 审计日志 + 安全策略                      | —                                                     | —                                            |
| **Settings**  | 全局配置 / 服务接入配置 / 租户支付渠道配置兜底      | 通用配置 + 打印模板 + 租户支付渠道配置 + 租户审计日志 | —                                            |
| **Role**      | 平台+租户角色模板管理                               | 本租户角色+权限配置                                   | —                                            |
| **Notice**    | 创建 / 发布 / 删除公告                              | 接收 / 阅读公告                                       | —                                            |
| **Ticket**    | 分派 / 回复 / 关闭工单                              | 无独立工单操作入口                                    | —                                            |

### 关键设计原则

1. **同一资源、不同视角**：Admin 获取跨租户数据，Tenant 只获取本租户数据，H5 只获取单个公开订单页面所需数据。
2. **租户隔离由后端注入**：Tenant 请求不传 `tenantId`，后端从 Token 中解析并注入查询条件。
3. **H5 入口令牌不是身份鉴权**：`orders.qrCodeToken` 的业务语义等同 `h5EntryToken`，仅用于打开 `/pay/:token` 对应订单 H5 页面，不承载收货人身份认证，也不是支付单标识。
4. **Admin 订单域只做审计**：订单导入、打印、催款等动作保留在 Tenant 端，Admin 端只保留跨租户查单和详情审计能力。

## 四、关键业务边界

### 4.1 H5 收款边界

- H5 通过 `/pay/:token` 访问订单公开详情，`token` 指 H5 入口令牌。
- H5 收款状态使用 `unpaid`、`paying`、`pending_verification`、`paid`、`expired` 五态。
- 在线支付只在用户主动发起时创建支付尝试；支付状态轮询仍使用同一个 H5 入口令牌，不暴露网关内部单号作为前端路由凭证。
- 在线支付必须同时满足订单可支付、租户已设置 `activePaymentChannel`、当前生效渠道配置状态为 `available`。
- 线下登记进入 `pending_verification`，由 Tenant 财务核销后写入收款流水。

### 4.2 Tenant 业务边界

- Tenant 侧所有业务数据自动按当前 `tenantId` 隔离。
- 订单导入采用“默认模板 / 租户模板 → 预检 → 正式导入 → 导入任务轮询”的链路；预检同步返回，正式导入异步执行。
- 手工订单、导入订单、打印回执、催款提醒均属于 Tenant 订单域职责。
- `/settings/general` 采用“平台默认 + 租户覆盖”模型，Tenant 端只更新通知与业务偏好覆盖层，不修改企业主体字段。
- `/settings/roles` 与 `/settings/permissions` 是固定角色和权限树的只读接口。
- 打印配置只存黑盒 JSON，持久化维度为 `tenantId + importTemplateId`。
- 支付渠道配置以 `channel` 为资源维度，实际收款渠道由租户主记录上的 `activePaymentChannel` 表达。

### 4.3 Admin 运营边界

- Admin 用户 `tenantId = null`，可以跨租户查看和管理平台运营数据。
- 租户中心负责租户生命周期、审核、续费、状态变更和支付渠道兜底管理。
- Admin 可以查看跨租户订单与收款数据，但不承担 Tenant 侧订单导入、打印和催款动作。
- 平台级计费、合同、发票、服务商、公告、工单、安全策略和系统配置属于 Admin 运营域。
- Admin 对租户支付配置的操作是运营兜底，不替代 Tenant 侧的渠道配置归属。

### 4.4 共享契约边界

- `docs/api` 负责业务语义、状态流转、权限边界和字段含义。
- `packages/types/src/enums` 负责闭集枚举值，不在 API 文档中维护第二份枚举定义。
- `packages/types/src/contracts` 负责前端可消费的请求与响应结构投影，不独立发明业务语义。
- Swagger / OpenAPI 负责联调展示，不反向定义业务事实。
